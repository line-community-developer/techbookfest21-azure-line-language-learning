# Azure / LINE での動作確認

[README](../README.md) / 前：[Foundry の設定](foundry-agent-setup.md)

Foundry の設定を終えたら、スマートフォンの LINE で演習と会話を試します。

## 1. Webhook の有効化・検証と公式アカウントの友だち追加

1. LINE Developers コンソールで Messaging API チャネルを開きます。
2. Messaging API 設定の Webhook URL が、配備した Functions の `https://<Default domain>/api/line/webhook` になっていることを確認します。
3. URL の「検証」を押し、成功したら「Webhook の利用」をオンにします。
4. 公式アカウントの友だち追加 URL または QR コードから友だち追加します。アプリの使い方案内が届くことを確認します。

検証が失敗する場合は [LINE 設定のトラブル対応](line-setup.md#困ったとき)を確認します。

## 2. ミニアプリで演習する

1. LINE Developers で控えた開発用のミニアプリ URL を開きます（PC で開くと、LINE で開くための QR コードが表示されます）。
2. ログイン・同意を求められたら画面に従い、ホームが表示されることを確認します。
3. 「文法」を開き、投入した文法項目と説明を確認します。
4. 「演習」で文法とレベルを選び、演習を開始します。問題に回答し、採点と解説を確認します。
5. 演習を終えて「履歴」を開き、回答結果が表示されることを確認します。一度ミニアプリを閉じて開き直しても結果を参照できます。

## 3. AI 講師と会話する

イタリア語の知識は不要です。日本語で挨拶を教えてもらうところから始めます。以下の送信文はそのままコピーして使えます。1 通ずつ、講師の返答を待ってから次を送ってください。

1. 公式アカウントのトークで `イタリア語は初めてです。「こんにちは」はイタリア語で何と言いますか？ 日本語の意味とカタカナの読み方も教えてください。` と送ります。
2. ローディング表示の後、講師 Giulia から挨拶の表現を紹介する返答が届くことを確認します。例として `Ciao（チャオ）` や `Buongiorno（ボンジョルノ）` などがあります。文章がこの例と同じである必要はありません。
3. `ありがとうございます。初対面の人には、どの挨拶を使うとよいですか？ 日本語で説明してください。` と送ります。前の話題に続けて、挨拶を使う場面について返答が届くことを確認します。
4. `最後に、「ありがとう」と「さようなら」も、イタリア語とカタカナの読み方を教えてください。` と送ります。質問に沿った表現が返ることを確認します。イタリア語を自分で入力したり、正しく発音したりする必要はありません。
5. 返答の「会話を終わる」を押します。終了案内にあるミニアプリ URL を開き、ホームの「最近の学習」から会話を選びます。
6. 分析の進捗と結果を確認します。挨拶についての日本語の質問だけでは、添削や復習項目が作られないこともあります。会話が保存され、分析が完了することを確認してください。復習項目が作られた場合は復習演習も開けます。

AI の文章や分析結果は毎回変わります。返答が質問と前の会話に沿っていることを確認してください。日本語だけで質問した場合、イタリア語の誤りがあると決めつけた添削や、発言していない内容に基づく復習は期待しません。

## 4. 管理画面を開く

1. ブラウザーで `https://<SWA のホスト名>/admin/login` を開きます。
2. 招待を受諾した GitHub アカウントでログインします。
3. 管理メニューから文法・問題・講師の一覧を開き、投入した教材が表示されることを確認します。

教材を編集したり、AI で問題を作成したりする操作は [管理画面](admin.md)を参照してください。

## エラーが出たとき

- Webhook・ミニアプリ認証・LINE 送信：[LINE の設定](line-setup.md#困ったとき)
- 講師・MCP・モデル接続：[Foundry の設定](foundry-agent-setup.md#困ったとき)
- 教材の投入・通常パッケージへの復元：[シード投入](cloud-seed-initialization.md#再実行失敗時)

LINE で講師から返答がない場合や、「いま講師が返事をできません」と届く場合は、次の手順で原因を確認します。

1. エラーが出た操作と時刻を控えます。
2. Azure ポータルで対象の Function App に接続された **Application Insights** を開きます。
3. **Failures（失敗）** で対象時刻の要求や例外を探します。表示されない場合は時間範囲を確認し、ログの反映を待って更新します。
4. 例外の詳細と、内側の例外（Inner exception）があればそのメッセージを確認します。講師との会話では `CallTutorAgent` の失敗が手掛かりになります。

`Foundry Agent Service returned HTTP 429.` が出ている場合は、Foundry 側のレート制限や一時的な混雑が考えられます。LINE での連続送信を止め、数分待ってから短いメッセージを 1 通送り、返答を待ってください。一時的な制限なら、設定を変更せずに再び返答が届くことがあります。

待っても 429 が続く場合は、同じ操作を繰り返さず、Foundry のモデルデプロイの TPM / RPM と利用状況、Azure のサービス稼働状況を確認します。429 だけで TPM 不足とは断定できません。[Foundry の制限と 429 の確認方法](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/quota)

ログを相談先へ共有するときは、例外メッセージと発生時刻を伝え、キー・トークン・会話本文などの個人情報は含めないでください。

## 検証後の片付け

Azure ポータルで**今回作成したリソースグループ名と中身を確認して**削除します。必要なデータは事前に保存してください。
LINE の開発用 Webhook を停止し、不要な GitHub Secrets を削除します。予算アラートは支出を自動停止する仕組みではありません。
削除は RG の概要 →「リソースグループの削除」から行います。対象名を入力して確認し、完了後に一覧から消えたことを確認します。[RG の管理・削除](https://learn.microsoft.com/ja-jp/azure/azure-resource-manager/management/manage-resource-groups-portal)
