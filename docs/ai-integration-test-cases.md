# AI 連携・画面結合テストケース

コードを変更した場合に、画面・API・会話分析ワークフローを確認する開発者向けの手動テストです。ハンズオンの操作確認は [Azure / LINE での動作確認](real-device-test.md)を参照してください。
各ケースを操作し、期待する結果を確認して判定を記録してください。デプロイ成功だけでは合格にしません。

## 対象と前提

- 対象: Azure 上の SPA → 同一オリジン BFF → Functions → Foundry / Azure OpenAI / Cosmos DB。
- AI: `gpt-5.4-mini`、deployment 名 `learning`。問題生成・品質評価・講師会話・会話分析を対象にします。
- 文法検索は Cosmos の参照マスターを使う Local 検索。AI Search は対象外です。
- 講師は保存済み Foundry Prompt Agent + remote MCP を使います。初期インフラと Functions を配備し、
  `Learning__TutorAgent=FoundryAgentService`、ProjectEndpoint、AgentName と固定 AgentVersion を確認します。
  [接続・エージェントの登録手順](foundry-agent-setup.md)を参照してください。
- 初期インフラの provisionだけでなく、対応する Functions と SPA/BFF のコードが配備済みであること。
- 文法・講師・サンプル問題のマスターが投入済みであること。初期化ワークフローやシードの再投入は、このテストでは実行しません。
- [LINE の設定](line-setup.md)を済ませ、ミニアプリは LINE アプリから開き、講師との会話は公式アカウントのトークで行います。テスト用の LINE アカウントで、原則一人ずつ実施します。
- 実データは変更され、AI の利用料金が発生します。既存の履歴は消さず、開始時の回答数・履歴と、今回作成するセッションの URL を記録します。
- ブラウザーの開発者ツールで Network のログ保持を有効にします。操作日時、URL、HTTP ステータス、応答のエラーコードを記録し、キー・トークンは共有しません。

## 判定方法

AI の文章は毎回変わります。文章の完全一致、特定のツール呼び出し順序、
誤りの検出件数の固定値では判定しません。内容の妥当性、処理の完了、保存の一貫性を確認します。
不自然な説明・誤採点・根拠のない観察は、通信成功でも不合格として記録します。

「画面で動くこと」と「実モデルが呼ばれたこと」は別です。投入済みセッションの表示や、
会話セッションの作成だけでは AI 接続の証拠になりません。
新規生成・新規メッセージ・新規分析を行い、IT-16 の確認も組み合わせます。
応答時間は実測値を記録します。タイムアウトや読み込み表示が解消しない場合は不合格です。

IT-07 / 08 で講師像・レベル・添削方針が維持され、
IT-09 で MCP ツールの実行と検索根拠が保存され、IT-16 で保存済み agent の名前・バージョンと
Functions MCP の実呼び出しを確認してください。MCP の列挙ができるだけでは合格にしません。
問題生成・分析ではモデルを直接呼び出します。
ポータルの Playground は画面結合テストの代わりにはなりません。

## 基本シナリオ

最初は **IT-01 → IT-02 → IT-04 → IT-05 → IT-07 → IT-08 → IT-10 → IT-11 → IT-12 → IT-16**
の順に実施します。その他は追加の分岐・回復確認です。

| ID | 確認対象・前提 | 操作手順 | 期待結果 |
| --- | --- | --- | --- |
| IT-01 | 初期表示・LINE ログイン・参照マスター | LINE アプリからミニアプリを開く。`/miniapp/practice`、`/miniapp/grammar` へ移動し、文法一覧の任意の項目を開く。 | LINE ログイン後にホームが開き、自分の LINE の表示名が出る。ホームの統計、演習の文法選択肢、文法詳細が表示される。参照データ不足や通信エラーがない。文法詳細の未監修表示は不具合と扱わない。これは AI 呼び出しの確認ではない。 |
| IT-02 | 指定項目で新規問題生成 | `/miniapp/practice` で A2 を選び、同レベルの文法項目を一つ選択。「選んだ項目で演習（1）」を一度押す。生成時間と遷移後の URL を記録。 | 「問題を生成しています…」が表示され、完了後 `/miniapp/practice/<sessionId>` に遷移。問題・指示・対象文法が表示され、選択した文法とレベルに整合する。原則5問を要求するが、表示数も記録する。不足・品質上の疑義は調査対象とし、固定応答で成功扱いにしない。 |
| IT-03 | おすすめ・別導線の生成 | `/miniapp/practice` の「おすすめ問題を自動生成」を押す。別途、文法詳細にある演習開始ボタンでも開始する。 | それぞれ新規演習が表示される。おすすめは表示レベル・学習状況に、文法詳細からはその文法に沿う。ホームの「続きから演習する」は既存セッションの再開なので、新規生成の証拠にしない。 |
| IT-04 | 回答・採点・解説 | IT-02 の演習で、解答可能な問題には正しい回答を、別の問題には明らかな誤答を入力。「回答する」→「次の問題へ」で進む。入力式なら空欄・空白だけの状態も確認する。 | 正誤、正解、解説が表示され、回答済み数が一つずつ増える。誤答を正解としない。結果確認前に勝手に次の問題へ進まない。空欄・空白だけでは送信できない。入力式／選択式は実際に生成された形式について確認し、出現しなかった形式は未実施とする。採点自体を毎回 AI が行うとは判定しない。 |
| IT-05 | 演習の保存・再開 | 1～2問回答後、「中断してホームに戻る（あとで再開できます）」を押す。ホームの再開導線または `/miniapp/history` から同じ演習を開き、ブラウザーを再読み込み。 | 同じセッションが開く。問題文や回答済み結果が保持され、未回答の問題から続けられる。再開だけで別の問題に置き換わらない。 |
| IT-06 | 演習完了・履歴整合 | 全問回答し「演習を終了して結果を見る」を押す。結果、`/miniapp/history`、ホームを確認。結果ページも再読み込み。 | 「演習結果」に正解数・総問題数・正答率・問題のふりかえりを表示。履歴の当該演習と一致する。ホームの回答数などの増分は開始前と今回の回答に整合する。再読み込みで二重計上されない。 |
| IT-07 | AI 講師の実応答（LINE） | 公式アカウントのトークで `Ciao! Vorrei ordinare una pizza. Che cosa mi consigli?` を送る。送信時刻を記録する。 | ローディング表示の後に、講師（送信者名 Giulia）から注文の相談に沿った返信が届く。添削がある場合は別の吹き出しで届き、最後の吹き出しに「会話を終わる」が付く。ミニアプリのホームの「最近の学習」にこの会話が出る。 |
| IT-08 | 会話文脈・連投 | 続けて `Non mangio carne. Puoi consigliarmi qualcosa senza carne?` を送る。返信を待たずに `E da bere?` も送る。 | 肉を避ける条件と注文の文脈に沿った返答になる。連投しても返信が混ざらず、送った順に1件ずつ返答される。同じ返信が重複して届かない。 |
| IT-09 | ツールと文法根拠 | トークで `Puoi cercare nelle regole di grammatica l'uso di piacere e spiegarmi perché si dice "Mi piacciono le pizze"?` と送る。 | 検索された文法に沿う説明になる。ツール実行と参照 ID は、Cosmos の `TutorSessions`・`TutorToolTurns` の記録で確認する（トークには表示しない）。文章が返るだけではツール連携の合格にしない。ツール未使用ならその事実を記録し、この観点は未確認とする。 |
| IT-10 | 会話終了・分析 | トークで `Ieri ho mangiato una pizza. Mi piace le pizze.` と送る。返信後に「会話を終わる」を押す（または「終了」と送る）。ミニアプリのホームの「最近の学習」からこの会話を開く。 | 終了のメッセージ（ミニアプリの URL 付き）が届く。ミニアプリの会話のふりかえりで「会話分析ワークフロー」が表示され、各段階の状態と最終結果が分かる。抽出された観察は実際の発言に根拠があり、「Mi piace le pizze」の一致の誤りを妥当に扱う。AI 推定の内容・件数は記録し、存在しない発言を捏造していないことを確認する。 |
| IT-11 | 分析から復習作成 | IT-10 のワークフローを確認し、「復習演習を開く →」または「ホームで復習プランを見る →」へ進む。 | `load-conversation`、`extract-observations`、`update-profile`、`plan-review` が成功。復習対象がある場合は `generate-questions`、`validate-questions`、`save-practice-session` まで成功し、復習演習を開ける。復習は対象文法と根拠に沿う。ワークフローは5問を目標とし、検証済み3～5問を保存可能。3問未満で成功扱いにしない。 |
| IT-12 | 復習の消化・永続化 | 作成された復習演習に1問回答。ホームの当該プランの「復習演習を続ける」から再開し、全問回答して終了。ホーム・履歴を再読み込み。 | 同じ復習演習を再開できる。完了後は結果が保持され、プランに完了状態や「前回の復習結果を見る」「もう一度復習する」が表示される。履歴の観察では会話由来の「AI推定」と、採点由来の「確定」が区別される。 |
| IT-13 | 復習不要の分岐 | トークで文法的に自然な短い挨拶だけを送り、会話を終える。 | 復習対象がなければ後段の生成・保存がスキップされても正常。空の復習演習を作らず、ワークフロー全体は正常終了する。AI が必ず観察ゼロにするとは限らないので、既存の観察も含めて復習根拠を確認する。 |
| IT-14 | 入力制約・操作中の制御 | 演習の文法項目を3つ選び4つ目を押す。トークで500文字を超える文章、スタンプ、画像を送る。会話が続いていないときに「終了」と送る。 | 文法選択は最大3項目。500文字を超える文章には、短く分けて送るよう案内が届く（講師は呼ばれない）。スタンプ・画像には反応しない。会話がないときの「終了」には、続いている会話がない旨が届く。 |
| IT-15 | 再生成 | 完了した復習プランの「もう一度復習する」を押す。 | 新しい演習 URL が発行される。前回の結果を上書きせず保持し、今回の問題も対象文法に沿う。確率的生成のため、全問題が必ず前回と異なることは条件にしない。 |
| IT-16 | 実 AI 接続の裏付け | IT-02、07、10 の時刻・セッション ID と、Functions（`LineWebhook`・`ConversationOrchestrator`）/ Foundry Agent Service / モデルの利用状況・既存ログを照合する。 | 会話について保存済み agent の名前・固定バージョンと MCP 実行を確認する。新規生成・分析は直接モデル呼び出しの成功と使用量を確認する。品質評価の実行はサーバー側情報で確認し、画面だけで判定しない。画面からの API は同一オリジン `/api/learning/...` で、ブラウザーが Foundry を直接呼ばず秘密のキーを保持しない。照合できなければ「画面正常・実呼び出し詳細未確認」と記録する。 |

## 障害・回復シナリオ

通常試験に加え、障害が発生したときに使用します。
**試験のために Azure 設定・RBAC・quota・マスターを変更したり、データを削除したりしません。**
意図的なサーバー障害注入は、別途承認した隔離環境でのみ実施します。

| ID | 条件・操作 | 期待結果・確認点 |
| --- | --- | --- |
| ER-01 | ブラウザーの開発者ツールで一時的にオフラインにし、問題生成を一度実施。オンラインに戻す。 | エラーを画面表示し、固定問題で成功を装わない。再試行で生成できる。 |
| ER-02 | 実際にモデル接続の403・429・タイムアウト等が発生した場合、操作と Network 応答を記録。原因解消後、元の画面から再試行。 | エラーが明示され、読み込み状態から戻る。モデル起因の403/429はアプリ側で503等に変換される場合があるため、ブラウザーとバックエンドの HTTP ステータスを混同しない。再試行後に成功し、架空の成功データが残っていない。 |
| ER-03 | 会話分析ワークフローが「失敗」した場合、失敗ステップ・コードを記録。原因解消後にパネルの「再実行」を押す。 | 同じワークフローを再開し、完了済み処理の成果を保持する。復習プラン・演習・観察が二重に増えない。会話のふりかえりを再読み込みしても結果を取得できる。自然発生しなければ未実施とする。 |
| ER-04 | 分析が待機中・実行中のままになった場合、約1分を目安に状態を記録し、一度再読み込み。 | 最新のサーバー状態を取得できる。現画面の自動ポーリングは2秒間隔・最大90回（約3分）のため、表示が止まっただけでバックエンド失敗と断定しない。再読み込み後も進行しなければログと照合し、不合格・調査対象とする。「再実行」は失敗時にのみ表示される。 |
